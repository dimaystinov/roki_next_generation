# Отказ NCS2 не завершает программу робота

`Neural` запускает `Soccer.Vision.neural_worker` через **тот же `sys.executable`**,
которым запущен робот. Новый Python и согласованные runtime/plugin/bindings OpenVINO 2026 остаются обязательными.
Старый Python, старый OpenVINO runtime и отдельный устанавливаемый сервис
не используются. Новый дочерний процесс нужен для изоляции зависаний и
аварий нативной библиотеки: перехват Python-исключений внутри процесса робота
не защищает от segfault/abort.

Камера и управление роботом остаются в основном процессе. Он копирует BGR
кадр в один переиспользуемый mmap. На Linux это анонимный memfd в RAM,
ёмкость 16 MiB; пиксели не сериализуются в JSON и не конвертируются дополнительно.
Дочерний процесс выполняет существующие letterbox, inference и NMS.
По приватному socketpair передаются только размер/номер запроса, тип объекта
и найденный центр. Публичных портов нет. Одновременно выполняется один запрос;
параллельный вызов не создаёт очередь и возвращает отсутствие обнаружения.

При USB-исключении, разрыве соединения, выходе процесса или истечении срока:

- Результат отказавшего запроса — `(0, 0)`, `is_ready()` — `False`.
- Причина доступна в `neural.error` и журнале.
- Дочернему процессу посылается SIGKILL, ожидание его завершения ограничено.
  Деструкторы OpenVINO не исполняются в процессе робота.
- Поиск мяча и оценка его скорости переключаются на цветовые алгоритмы
  в том же вызове, с новым снимком. Нейрорезультаты до сбоя не используются
  для цветовой оценки скорости.
- Следующие обращения не запускают inference и не повторяют ожидание.

По умолчанию `ROKI_NCS2_TIMEOUT=1` с на ответ, `ROKI_NCS2_STARTUP_TIMEOUT=15` с
на готовность после запуска Python. Значения должны быть конечными и больше
нуля. Завершение ребёнка добавляет до 0.2 с ожидания. Это пределы ожидания IPC,
а не гарантия жёсткого реального времени: создание процесса, планировщик и
сбой самого ядра ОС находятся за пределами этой защиты. Подобрать inference
таймаут по замерам на CM4, включая прогрев первого кадра.

Автоматического переподключения нет. После устранения USB-проблемы можно явно
вызвать `glob.neural_vision_enable()`; предыдущий дочерний процесс закрывается.
При обычном завершении используется `close()`/atexit; Linux parent-death signal
завершает ребёнка и при аварийном выходе родителя. Перезапуск сети не требует
перезапуска камеры. Библиотечный плагин этой правкой не меняется.

## Проверка

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q tests/test_neural.py tests/test_neural_isolation.py`

Проверки запускают настоящие дочерние Python-процессы с тестовой заменой
аппаратного OpenVINO API: корректные результаты нескольких кадров, USB-ошибка,
зависание и аварийный выход при старте/обработке, смерть между запросами,
повторные обращения после отказа, закрытие/повторный запуск, переход Vision
на цветовой путь. Это проверка изоляции, **не проверка инференса на NCS2**.

На голове ещё нужны испытания: извлечь NCS2 во время инференса, проверить
продолжение стратегии/камеры/STM; убедиться в работе цветовых порогов с текущей
камерой; вставить устройство и явно перезапустить детектор; измерить худшую
задержку первого кадра. Физический CM4/NCS2 в текущей среде отсутствует.

Встроенный MYRIAD форка 2026.5 используется без повторной регистрации.
Явный путь плагина выбирается через отдельную XML-конфигурацию Core.
Это также позволяет проверить приложение с тестовым плагином, не добавляя
его кандидатом к production MYRIAD. Конфигурация содержит только путь
библиотеки и удаляется после создания Core.
